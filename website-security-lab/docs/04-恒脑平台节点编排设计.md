# 04 · 恒脑平台节点编排设计

> 依据平台提供的节点类型（**开始 / 结束 · 模型节点 · 工具节点 · 智能体节点 · 交互节点 · 代码节点 · 自规划节点**）搭建智能体框架，
> 并给出"赛题每项功能 → 由哪些节点组成"的对照表。
> 节点编排图见 `docs/assets/node_flow.svg`（配套 PNG：`docs/assets/node_flow.png`）。

## 一、七类节点在本智能体中的分工

| 节点类型 | 在本智能体中的职责 | 典型用法 | 使用红线 |
| --- | --- | --- | --- |
| **开始节点** | 流程入口，定义触发方式与入参 | 定时器（周期巡检）/ 手动触发（应急复测）；入参：资产、授权编号、任务 ID | 一次开始只对应一轮巡检，避免一次触发扫全量 |
| **模型节点** | 自然语言理解、规则生成、初判、分级解释、报告撰写 | 敏感定义转正则、误报初判、风险分级说明、影响与修复建议、报告正文 | 必须约束**结构化输出**（JSON），禁止直接把工具原始输出当结论 |
| **工具节点** | 所有出站请求与开源工具的**唯一出口** | 子域枚举、爬虫、指纹、模板化 POC、YARA/ClamAV、文档解析、告警通道、调度器 | 必须携带**安全档位（T0/T1/T2）+ 限速 + 超时**；T2 默认关闭 |
| **智能体节点** | 封装可复用的子流程（发现 / 检测 / 复核） | 资产发现智能体、检测编排智能体、复核确证智能体；也可封装完整巡检流程被平台直接调度 | 子智能体之间只读写共享数据，禁止互相直调，避免环形依赖 |
| **交互节点** | 人机协作与人工兜底 | 授权与敏感规则录入、回显确认、高危项人工裁决、工单分派、报告导出确认 | 每处交互都要有**超时与默认策略**，否则流程会被挂死 |
| **代码节点** | 确定性数据处理 | 范围/格式校验、URL 归一化、跨工具去重、风险分计算、基线对比、状态机、脱敏、审计落库 | 代码节点**不发起网络请求**，一切请求交工具节点 |
| **自规划节点** | 动态任务规划与失败重规划 | 按资产特征生成任务 DAG、工具不可用时降级改道、复测计划生成 | 必须注入**授权范围与预算为不可覆盖约束**，并限制候选工具集与最大步数 |
| **结束节点** | 输出结构化结果 | 返回 findings 清单、执行计划与审计摘要，供告警/报告/下一轮消费 | 需要区分"完整成功"与"部分成功"，不能吞掉失败状态 |

## 二、主流程：一次周期巡检

```mermaid
flowchart LR
  S([开始 · 定时/手动]) --> I1[交互 · 授权录入]
  I1 --> C1[代码 · 合规闸门]
  C1 --> P1[自规划 · 任务规划]
  P1 --> A1[智能体 · 资产发现]
  A1 --> A2[智能体 · 检测编排]
  A2 --> C2[代码 · 归一化去重]
  C2 --> A3[智能体 · 复核确证]
  A3 --> M1[模型 · 分级与解释]
  M1 --> C3[代码 · 基线状态机]
  C3 --> T1[工具 · 告警通道]
  T1 --> M2[模型 · 报告生成]
  M2 --> I2[交互 · 人工复核]
  I2 --> E([结束 · 本轮闭环])
  E -. 基线/复测结果反哺 .-> P1
```

| 序号 | 节点 | 配置要点 |
| --- | --- | --- |
| 1 | **开始** · 定时/手动 | 定时器表达式（如 `0 2 * * *`）、时间窗、冻结期；或人工触发并传入资产 |
| 2 | **交互** · 授权录入 | 表单：域名/IP段/URL前缀、有效期、责任人、授权书附件；巡检范围与排除规则 |
| 3 | **代码** · 合规闸门 | 授权有效性、范围匹配、排除规则、档位授权、请求预算与限速令牌初始化 |
| 4 | **自规划** · 任务规划 | 输入资产指纹 + 历史记忆；输出子任务 DAG（含选择理由、档位、预算） |
| 5 | **智能体** · 资产发现 | 调用子流程② |
| 6 | **智能体** · 检测编排 | 并行调用子流程③④⑤（漏洞 / 篡改挂马 / 敏感信息） |
| 7 | **代码** · 归一化去重 | 统一 Finding 模型、跨工具合并、同源关联 |
| 8 | **智能体** · 复核确证 | 调用子流程⑥（只读复采、置信度打分） |
| 9 | **模型** · 分级与解释 | 依据风险分与证据生成分级理由、影响说明、分角色修复建议 |
| 10 | **代码** · 基线状态机 | 与上轮快照对比：新增 / 变更 / 修复 / 复现 |
| 11 | **工具** · 告警通道 | P0/P1 即时推送（邮件/Webhook/企业微信），其余汇总日报，静默窗口 |
| 12 | **模型** · 报告生成 | 汇总概览、明细、证据截图、整改建议、趋势 |
| 13 | **交互** · 人工复核 | 确认处置结论、标记误报、导出报告 |
| 14 | **结束** · 本轮闭环 | 输出结果并把基线/复测结论反哺至「自规划」节点（闭环） |

## 三、八条子流程的节点链

### 子流程① 授权与配置（要求①）

`开始` → `交互·录入授权与范围` → `代码·范围与格式校验` → `模型·敏感定义转规则` → `代码·写入配置规则库` → `交互·回显确认` → `结束`

- 模型节点负责把"本单位敏感信息"的自然语言描述转成关键词/正则/文件类型/样例指纹，并**输出匹配理由**。
- 代码节点负责正则语法校验、规则去重与生效，避免"配了但没生效"。

### 子流程② 资产与页面发现（要求②）

`开始` → `工具·子域枚举/DNS` → `工具·存活探测与指纹` → `工具·爬虫+JS提取` → `代码·URL归一化入库` → `代码·与上轮快照Diff` → `模型·技术栈研判` → `结束`

### 子流程③ 漏洞与弱配置检测（要求②）

`开始` → `工具·组件CVE比对` → `工具·模板化POC` → `工具·安全头/CORS/TLS` → `工具·备份/调试端点` → `代码·标准化为Finding` → `模型·误报初判与定级` → `结束`

### 子流程④ 篡改 / 挂马 / 恶意外链检测（要求②）

`开始` → `工具·整页渲染截图` → `代码·正文/DOM基线比对` → `工具·YARA/ClamAV特征` → `工具·外链信誉比对` → `模型·篡改类型与证据` → `结束`

### 子流程⑤ 敏感信息泄露检测（要求②）

`开始` → `工具·文档与内容抽取` → `代码·关键词/正则/样例` → `代码·白名单过滤+脱敏` → `模型·敏感性上下文判定` → `结束`

### 子流程⑥ 去重 · 验证 · 分级 · 解释（要求③）

`开始` → `代码·跨工具去重合并` → `智能体·非破坏性确证` → `模型·风险分级定级` → `模型·影响与修复建议` → `交互·低置信度裁决` → `结束`

### 子流程⑦ 闭环运营（要求④）

`开始` → `代码·基线对比与状态机` → `模型·告警分级与摘要` → `工具·告警通道推送` → `交互·工单分派与确认` → `工具·复测重放检测项` → `模型·报告生成与导出` → `结束`

### 子流程⑧ 合规与审计（贯穿所有检测）

`开始` → `代码·Scope校验与限速` → `工具·出站请求代理` → `代码·审计日志落库` → `交互·越界拦截告警` → `结束`

> 这条子流程被③④⑤等所有检测子流程**前置调用**：工具节点的全部出站请求统一经由「工具·出站请求代理」出口，
> 实现范围校验、限速与审计留痕——这是"授权边界不可绕过"的工程保证。

## 六、编排注意事项（评委容易追问的点）

1. **自规划节点是最大风险点**：它能自主决定"下一步做什么"，也可能规划出范围外目标。必须把授权范围、排除路径、档位与请求预算作为**不可覆盖的约束**注入，并限制候选工具集与最大步数。
2. **工具节点必须是唯一出口**：所有网络请求集中在工具节点，才能保证限速、档位与审计不被绕过；代码节点只做本地计算。
3. **交互节点要有超时与默认值**：演示时最容易卡死的就是等待人工输入；超时应自动降级为"暂存待人工处理"而不阻塞整单。
4. **模型节点约束结构化输出**：敏感规则生成、分级、修复建议都要求 JSON 输出并做字段校验，避免自然语言结论直接进入报告。
5. **智能体节点只做封装，不重复实现**：资产发现、检测编排、复核确证各封装一次，主流程与子流程复用同一份逻辑，便于独立调试与平台单独调度。
6. **失败隔离**：单个工具节点失败应降级到替代工具或跳过，不能让整个流程失败（由自规划节点接管改道）。

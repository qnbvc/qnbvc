# 05 · 子流程① 授权与配置 —— 完整流程设计

> 这是整个智能体的**合规地基**：后面所有检测（漏洞 / 篡改 / 挂马 / 敏感信息）能扫什么、扫多快、在什么时间扫，
> 全部由这条子流程产出的配置对象决定。节点编排图见 `docs/assets/subflow1.svg`。

---

## 一、定位

| 项 | 内容 |
| --- | --- |
| 触发方式 | 人工发起（平台表单 / 对话指令）、配置变更（改范围、改规则）、批量导入 |
| 输入 | 授权信息、巡检范围、周期策略、敏感信息定义（关键词/正则/文件类型/样例） |
| 输出 | **ScopeSnapshot（授权范围快照，带版本号）** + **SensitiveRuleSet（敏感规则集）** + 校验报告 + 审计记录 |
| 下游消费 | 子流程⑧ 合规闸门读 ScopeSnapshot；子流程⑤ 读 SensitiveRuleSet；调度器读 Schedule |
| 成功判据 | 配置校验零错误、授权书与录入范围一致、规则可编译且命中预览符合预期、已入库并下发 |

一句话：**这条流程的产出物是"边界"，边界一旦写错，后面所有检测都会越界或漏检。**

---

## 二、完整节点链（展开 13 个节点）

设计图上是 7 个节点（开始 → 交互 → 代码 → 模型 → 代码 → 交互 → 结束）。实际落地时，
"录入"要拆成三类表单（授权/范围/敏感规则）、"校验"要区分格式校验与规则编译、还要补上权限校验、
授权书交叉核对与生效下发，因此展开为 13 个节点：

```
① 开始 · 发起授权配置
② 代码 · 权限与角色校验
③ 交互 · 授权基础信息录入
④ 交互 · 巡检范围与策略录入
⑤ 交互 · 敏感信息定义录入
⑥ 代码 · 输入规范化与格式校验
⑦ 模型 · 授权书要素抽取与交叉核对
⑧ 模型 · 敏感定义转检测规则
⑨ 代码 · 规则编译与冲突检测
⑩ 交互 · 回显确认（含红黄线提示）
⑪ 代码 · 配置入库与版本快照
⑫ 代码 · 生效下发与下游通知
⑬ 结束 · 返回配置对象与校验报告
```

异常回退：⑥ 校验失败 → 回 ③/④/⑤；⑦ 核对不一致 → 回 ③ 人工裁决；⑨ 规则冲突 → 回 ⑤；② 无权限 → 直接 ⑬ 拒绝。

| # | 节点类型 | 名称 | 输入 | 输出 |
| --- | --- | --- | --- | --- |
| ① | 开始 | 发起授权配置 | 申请人、单位、操作类型（新建/变更/停用）、request_id | 流程上下文 |
| ② | 代码 | 权限与角色校验 | 申请人角色 | 放行 / 拒绝（写审计） |
| ③ | 交互 | 授权基础信息录入 | 授权编号、主体、资产、有效期、责任人、授权书附件 | 授权信息草稿 |
| ④ | 交互 | 巡检范围与策略录入 | 含/排除规则、深度、并发、预算、时间窗、档位 | 范围策略草稿 |
| ⑤ | 交互 | 敏感信息定义录入 | 关键词、正则、文件类型、样例、白名单、脱敏策略 | 敏感规则草稿 |
| ⑥ | 代码 | 输入规范化与格式校验 | 三份草稿 | 规范化配置 + 错误清单 |
| ⑦ | 模型 | 授权书要素抽取与交叉核对 | 授权书文件 + 录入范围 | 抽取要素 + 一致性结论 |
| ⑧ | 模型 | 敏感定义转检测规则 | 自然语言描述 + 样例 | 结构化规则 + 理由 + 误报提示 |
| ⑨ | 代码 | 规则编译与冲突检测 | 结构化规则 | 可运行规则集 + 冲突报告 |
| ⑩ | 交互 | 回显确认（红黄线提示） | 生效对象 + 命中预览 | 确认 / 退回 |
| ⑪ | 代码 | 配置入库与版本快照 | 已确认配置 | ScopeSnapshot vN + 变更 diff + 审计 |
| ⑫ | 代码 | 生效下发与下游通知 | 快照版本号 | 缓存刷新 + 调度重排 + 规则版本下发 |
| ⑬ | 结束 | 返回配置对象与校验报告 | 全部产物 | 配置对象 / 拒绝原因 |

## 三、逐节点设计

### ① 开始节点 · 发起授权配置

| 配置项 | 值 |
| --- | --- |
| 触发 | 人工（表单 / 对话）、变更申请、批量导入 |
| 入参 | `applicant`、`tenant`、`action`（`create` / `update` / `disable`）、`draft_id`、`request_id` |
| 幂等键 | `request_id`，重复提交直接返回上次结果 |

> 对话式入口（演示加分项）：用户说"给 portal.example.gov.cn 加一条敏感词『内部资料』，周期改成每天凌晨 2 点"，
> 由模型节点解析成结构化表单初值，再进入 ③④⑤ 的人工确认。

### ② 代码节点 · 权限与角色校验

| 角色 | 可改授权范围 | 可开 T1 | 可开 T2 | 可改敏感规则 | 可审批 |
| --- | --- | --- | --- | --- | --- |
| 管理员 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 运营 | ✗ | ✓ | ✗ | ✓ | ✗ |
| 只读 | ✗ | ✗ | ✗ | ✗ | ✗ |

- 拒绝时写审计（谁、何时、想做什么、为什么被拒），并直接跳到 ⑬ 结束节点返回拒绝原因。
- **注意**：这是授权变更的权限校验，与子流程⑧ 执行期的范围校验是两回事，两者都要有。

### ③ 交互节点 · 授权基础信息录入

| 字段 | 必填 | 校验 | 示例 |
| --- | --- | --- | --- |
| 授权编号 | ✓ | 唯一、格式 `AUTH-YYYY-MMDD-NNN` | `AUTH-2026-0912-001` |
| 授权主体单位 | ✓ | 与授权书一致 | 某单位 |
| 域名 / 通配子域 | ✓ | 域名语法，`*.` 仅覆盖子域 | `portal.example.gov.cn`、`*.example.gov.cn` |
| IP 段 | ✗ | CIDR 语法 | `203.0.113.0/24` |
| URL 前缀 | ✗ | 必须 `https://` | `https://portal.example.gov.cn/` |
| 有效期 | ✓ | `start < end`，且未过期 | 2026-09-01 ~ 2026-12-31 |
| 责任人 + 联系方式 | ✓ | 手机号/邮箱格式 | 张某某 / secops@example.gov.cn |
| 授权书附件 | ✓ | PDF/图片，≤20MB，哈希去重 | `auth-2026-0912.pdf` |
| 备注 | ✗ | 长度限制 | 含约定：禁止主动测试 |

- 交互设计：分步表单 + 草稿自动暂存 + 上次值回填 + 通配符实时提示 + 附件秒传与查重。
- 超时策略：草稿保留，超时未提交则提醒责任人，**不阻塞其他流程**。

### ④ 交互节点 · 巡检范围与策略录入

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| 包含路径 | `/` | 支持前缀与通配 |
| 排除路径 | 空 | 如 `/admin/export`、`/api/personal/*`，命中即拒绝请求 |
| 排除规则 | 空 | 如 `*?download=*` |
| 端口范围 | 443 | 非 80/443 需显式授权 |
| 爬取深度 | 2 | 越大请求量越大 |
| 并发 | 4 | 与限速联动 |
| 单次请求预算 | 20000 | 超预算自动停止并记录 |
| 时间窗 | 02:00-05:00 | 窗口外的请求直接拒绝 |
| 冻结期 | 空 | 如重大活动日 |
| 默认档位 | T0（被动） | T1/T2 需显式开启 |
| T1 资产白名单 | 空 | 列出的资产才允许受控探测 |
| T2 资产白名单 | 空 | 需二次确认 + 管理员审批 |

### ⑤ 交互节点 · 敏感信息定义录入

三种录入方式，可混用：

1. **手填**：关键词、正则（名称 + 表达式 + 说明）、文件类型。
2. **自然语言**：一句话描述 → 交给 ⑧ 模型节点转规则（推荐，降低使用门槛）。
3. **样例上传**：上传样例文件/片段 → 代码节点生成指纹（分片哈希 + 归一化）→ 全网比对。

| 字段 | 示例 |
| --- | --- |
| 关键词 | 内部资料、仅供内部使用 |
| 正则 | 中国大陆手机号 `(?<!\d)1[3-9]\d{9}(?!\d)`、身份证号、AccessKeyId |
| 文件类型 | pdf、docx、xlsx、csv、sql、bak、env、log |
| 样例 | `sample-report.docx`（自动生成指纹） |
| 白名单 | `13800000000`（示例数据，命中不告警） |
| 脱敏策略 | 部分脱敏（保留首尾 3 位）/ 全掩码 |
| 生效范围 | 全站 / 指定路径 |

### ⑥ 代码节点 · 输入规范化与格式校验

> 这一节点是"确定性的守门人"，所有规则都在这里被机械校验，不依赖模型判断。

| 校验分组 | 规则 |
| --- | --- |
| 域名 | 语法合法；`*.` 仅覆盖子域；重复项合并；**禁止 `*` 裸通配** |
| IP / CIDR | `ipaddress` 解析；网段 ≤ /16（过大需审批） |
| URL 前缀 | 必须 `https://`；必须落在域名/IP 范围内 |
| 排除规则 | 排除路径必须**被包含范围覆盖**（否则提示"排除了一个本来不会扫的路径"） |
| 时间 | `valid_from < valid_until`；当前日期未过期；时间窗格式 `HH:MM-HH:MM` |
| 调度 | cron 五段表达式可解析；时间窗时长与单次巡检耗时匹配 |
| 数值 | 并发 1~32；深度 0~5；单次预算 100~200000 |
| 敏感规则 | 正则**必须可编译**；长度限制；关键词去重与去空白 |
| 文件类型 | 必须在支持白名单内（pdf/docx/xlsx/csv/sql/bak/env/log/json/txt…） |
| 附件 | 格式、大小、哈希查重 |

错误码示例：`ERR-AUTH-001` 域名格式非法、`ERR-SCOPE-004` 排除路径不在范围内、`ERR-RULE-002` 正则编译失败、
`ERR-SCHED-001` cron 无法解析、`ERR-TIER-003` T2 资产未获审批。

### ⑦ 模型节点 · 授权书要素抽取与交叉核对

- 任务：从授权书（PDF/图片）抽取**授权主体、授权范围、有效期、盖章状态**，与人工录入值比对。
- 硬约束：**以授权书为准**。录入范围超出授权书范围 → 一律回退人工裁决，不允许"先扫了再说"。

输出 JSON：

```json
{
  "issuer": "某单位",
  "scope_domains": ["portal.example.gov.cn", "*.example.gov.cn"],
  "valid_from": "2026-09-01",
  "valid_until": "2026-12-31",
  "stamped": true,
  "extracted_from": "auth-2026-0912.pdf#p1",
  "mismatch": [
    {"field": "valid_until", "entered": "2026-12-31", "document": "2026-11-30"}
  ]
}
```

提示词要点：只做要素抽取与比对，**不要替用户补全或推测范围**；抽不到就留空并标注"需人工确认"。

### ⑧ 模型节点 · 敏感定义转检测规则

输入：自然语言描述 + 样例文本/文件。输出：结构化规则 + 匹配理由 + 误报风险提示。

```json
{
  "keywords": ["内部资料", "仅供内部使用"],
  "regex": [
    {"name": "单位内部编号", "pattern": "NB-\\d{4}-\\d{6}", "reason": "样例中该编号格式固定出现 3 次"}
  ],
  "file_types": ["docx"],
  "samples": [{"name": "sample-report.docx", "fingerprint_hint": "正文含『内部资料 请勿外传』"}],
  "whitelist_suggestions": ["示例数据 13800000000"],
  "false_positive_risks": [
    {"rule": "NB-\\d{4}-\\d{6}", "risk": "可能与公开的招标编号格式重合", "advice": "增加前后缀限定"}
  ]
}
```

提示词约束：正则必须可编译、禁止 `.*` 这类过宽模式、每个规则必须给出理由、必须显式列出误报风险与建议白名单。

### ⑨ 代码节点 · 规则编译与冲突检测

| 处理 | 说明 |
| --- | --- |
| 正则编译 | 逐条 `re.compile`；拒绝灾难性回溯模式（嵌套量词、超长重复） |
| 样例指纹 | 归一化（去空白/全角转半角）→ 分片 → 分片哈希集合 → 模糊匹配阈值 |
| 冲突检测 | 关键词与白名单互斥检查、规则与排除路径矛盾检查、与既有规则相似度查重 |
| 过宽告警 | 纯 6 位以上数字、单个汉字、长度 < 3 的关键词 → 标记为"高风险误报规则" |
| 命中预览 | 用样例页面/历史页面离线试跑，输出预计命中量（给 ⑩ 回显用） |

### ⑩ 交互节点 · 回显确认

展示四件事，然后人工确认：

1. 最终生效范围（含/排除，可视化域名与路径树）；
2. 周期与档位（T2 会显著标注）；
3. 敏感规则命中预览（预计命中条数 + 样例命中片段，已脱敏）；
4. 红黄线提示：`*.` 扩大范围、T2 主动档、过宽规则、有效期过短。

二次确认：开启 T2 或扩大范围超过 30% 时，要求管理员二次确认（可接平台审批流）。

### ⑪ 代码节点 · 配置入库与版本快照

| 实体 | 关键字段 |
| --- | --- |
| Authorization | id、编号、主体、附件哈希、有效期、责任人、状态 |
| Scope | 含/排除规则、端口、深度、并发、预算、时间窗、冻结期、档位白名单 |
| SensitiveRule | 类型、表达式/文件类型、优先级、白名单、脱敏策略、生效范围、来源（手填/模型/样例） |
| ConfigVersion | 版本号、快照 JSON、变更 diff、操作人、时间、审批记录 |

- 每次变更生成新版本，**支持回滚**；检测任务记录其使用的规则版本号，保证结果可追溯。
- 审计日志：谁、何时、改了什么（diff）、依据哪份授权书。

### ⑫ 代码节点 · 生效下发与下游通知

1. 刷新授权与规则缓存；
2. 通知调度器按新周期/时间窗重排任务；
3. 把规则版本号下发给检测子流程（避免新旧规则混用）；
4. 失败重试与告警（下发失败不得静默）。

### ⑬ 结束节点 · 返回结果

成功：返回 `ScopeSnapshot` 版本号 + `SensitiveRuleSet` 版本号 + 校验报告 + 审计 ID。
失败：返回拒绝原因（无权限 / 校验不通过 / 授权书不一致），并保留草稿供再次编辑。

## 四、异常分支与回退

| 场景 | 触发节点 | 处理 | 回到 |
| --- | --- | --- | --- |
| 申请人无权限 | ② 权限校验 | 拒绝并写审计 | ⑬ 结束（拒绝） |
| 域名/网段格式非法 | ⑥ 校验 | 定位到具体字段并给出错误码 | ③ / ④ |
| cron 无法解析 | ⑥ 校验 | 给合法示例 | ④ |
| 排除路径不在范围内 | ⑥ 校验 | 提示可能填错 | ④ |
| 正则编译失败 | ⑥ / ⑨ | 给出编译错误位置 | ⑤ |
| 规则过宽（高误报风险） | ⑨ 冲突检测 | 黄线提示 + 建议收紧 | ⑤（或强制确认） |
| 与既有规则重复 | ⑨ | 提示可复用已有规则 | ⑤ |
| 授权书与录入范围不一致 | ⑦ 交叉核对 | **以授权书为准**，人工裁决 | ③ |
| 开启 T2 未获审批 | ⑩ 回显确认 | 降级为 T1 或挂起审批 | ④ |
| 下发失败 | ⑫ 生效下发 | 重试 + 告警，任务标记"配置未生效" | ⑫ 重试 |

## 六、验收用例（自测清单）

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 正常新建 | 合法域名 + 全字段 | 校验通过、生成 v1 快照、下发成功 |
| 通配范围 | `*.example.gov.cn` | 通过并黄线提示"范围较大" |
| 裸通配 | `*` | 拒绝，ERR-AUTH-001 |
| 排除路径不在范围内 | 排除 `/private` 但包含仅为 `/news` | 黄线提示 |
| 非法正则 | `([0-9` | 拒绝，ERR-RULE-002，定位到 ⑤ |
| 过宽规则 | 关键词 `的` | 黄线提示高误报，需确认 |
| 白名单冲突 | 关键词与白名单同一值 | 拒绝或提示互斥 |
| 授权书不一致 | 录入有效期长于授权书 | 回退 ③，不允许生效 |
| 无权限操作 | 只读角色提交 | 拒绝并写审计 |
| 开启 T2 | T2 资产列表为空 | 拒绝，ERR-TIER-003 |
| 重复提交 | 同 `request_id` | 幂等返回上次结果 |

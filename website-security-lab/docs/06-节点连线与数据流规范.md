# 06 · 节点连线与数据流规范

> 回答"各个节点怎么连接"：**每条边从哪个节点的哪个出口，连到哪个节点的哪个入口，边上跑什么变量，什么条件才走这条边**。
> 连线图见 `docs/assets/wiring.svg`（配套 PNG：`docs/assets/wiring.png`）。

---

## 一、连线的五条基本规则

1. **端口匹配**：上一条边的「出」必须是下一条边的「入」。类型不匹配（如把 `findings[]` 接到要求 `report` 的入口）应连不上。
2. **单一出口 / 单一职责**：正常流程每个节点只有一个主出口；分支出口必须是显式条件边，不能靠"节点内部偷偷判断"。
3. **请求必经闸门**：任何会发起网络请求的边，都必须先经过 ③ 合规闸门或子流程⑧ 的「工具·出站请求代理」，不允许工具节点绕过。
4. **并行分支不互相连线**：并行的检测分支各自把结果写回**共享上下文**，由汇聚节点统一读取，避免环形依赖。
5. **环必须有退出条件**：自规划改道最多 2 次、复测环最多 3 轮，超限则降级为"待人工处理"，防止无限循环。

## 二、边的 8 种类型

| 类型 | 样式 | 用途 | 触发条件 |
| --- | --- | --- | --- |
| 主流程边 | 灰色实线 | 正常串联 | 上一步成功 |
| 条件边 | 绿色实线 | 条件成立才走 | 如 `changes.new` 非空且存在 P0/P1 |
| 并行分叉 fork | 蓝色实线 | 一个节点驱动多条子流程 | 无条件（并行执行） |
| 并行汇聚 join | 蓝色实线 | 多分支结果合并 | 全部分支返回，或单分支已降级 |
| 改道 / 回退边 | 橙色虚线 | 失败回到前序节点 | 校验失败 / 工具超时 / 降级无替代 |
| 阻断边 | 红色虚线 | 直接跳到结束 | 范围外 / 未授权档位 / 命排除路径 / 超预算 |
| 闭环反哺边 | 蓝色虚线 | 结束 → 自规划 | 每轮巡检结束（无条件） |
| 子流程调用边 | 红色实线（节点内部） | 智能体节点展开为子流程 | 由主流程节点显式调用 |

特殊边（旁路，不参与主链）：

| 边 | 类型 | 触发条件 | 动作 |
| --- | --- | --- | --- |
| ③ → ⑭ | 阻断 | 目标不在授权范围 / 命中排除路径 / 档位未授权 / 超出请求预算 | 拒绝本次请求，写审计，直接结束 |
| ⑥ → ④ | 改道 | 工具节点超时 / 失败 / 降级无替代 | 交回自规划重新选路，最多 2 次 |
| ⑧ → ⑬ | 转人工 | 二次确证未复现 / 置信度低于阈值 / 等级为 P0 | 旁路进人工裁决，结论回写误报库 |
| ⑩ → ⑪ | 条件 | `changes` 中 new/reopened 非空且含 P0/P1 | 即时告警；否则仅入库随日报汇总 |
| ⑭ → ④ | 闭环 | 每轮巡检结束 | 基线、误报库、命中率回流记忆 |

### ⑥ 检测编排节点的 fork / join

```
⑥ 智能体·检测编排
   ├─ fork → 子流程③ 漏洞 / 弱配置 ─┐
   ├─ fork → 子流程④ 篡改 / 挂马   ─┼─ join → ⑦ 代码·归一化与去重
   └─ fork → 子流程⑤ 敏感信息      ─┘
```

- 三条分支**彼此不连线**，各自把 `raw_findings[]` 写回共享上下文；
- 汇聚条件：三条全部返回，**或**某条已明确降级（此时在 `trace` 里留 `degraded` 标记，报告中说明"该维度本轮未覆盖"）；
- 汇聚前不做去重，去重统一在 ⑦ 完成，保证"多处命中同一条"能被识别为多来源互证。

## 五、主流程 ↔ 子流程的调用契约

智能体节点（⑤⑥⑧⑩）内部是子流程，对外只暴露一组入参 / 出参：

| 智能体节点 | 入参 | 出参 | 失败处理 |
| --- | --- | --- | --- |
| ⑤ 资产发现（子流程②） | `scope_snapshot`, `plan.discover` | `assets[]`, `pages[]`, `fingerprint` | 返回已发现部分，标记 `partial` |
| ⑥ 检测编排（子流程③④⑤） | `pages[]`, `ruleset_version`, `tier_policy` | `raw_findings[]`, `trace[]` | 单分支降级不影响整体，写 `degraded` |
| ⑧ 复核确证（子流程⑥） | `findings[]` | `findings[]`, `fp_marks[]` | 无法复采时保留原置信度并标注 |
| ⑩ 基线与状态机（子流程⑦） | `findings[]`, `baseline` | `changes{}`, `alerts[]` | 基线缺失时按"首轮"处理，不产出篡改结论 |

## 六、环、重试与中断恢复

| 环 | 退出条件 | 超限行为 |
| --- | --- | --- |
| ④ 自规划 → ⑥ 改道 → ④ | 工具成功 或 已有替代工具 | 重规划 > 2 次 → 该资产标记"未覆盖"，进报告备注 |
| ⑩ → ⑪ → 交互 → 复测 → ⑩ | 复测结果明确（已闭环 / 复现） | 复测 > 3 轮 → 转人工，不再自动重放 |
| ⑭ → ④ 闭环 | 每轮必然发生（非重试） | 不适用 |
| 交互节点等待 | 有超时（建议 24h） | 超时自动暂存草稿，不阻塞其他任务 |

## 七、上下文与变量规范

| 变量 | 产出节点 | 消费节点 | 说明 |
| --- | --- | --- | --- |
| `ctx` | ① 开始 | 全流程 | 租户、触发方式、request_id（幂等键） |

| `pages[] / assets[]` | ⑤ | ⑥⑦ | 页面树与资产清单 |

## 八、平台侧落地注意

1. **条件边**：若平台的条件分支支持表达式，直接写条件；若不支持，则由代码节点输出 `branch` 字段（如 `"alert"` / `"skip"`），再按端口分流。
2. **回环**：若画布不允许连成环，用「子流程递归调用」或把重规划逻辑放进自规划节点的内部迭代，并显式设置最大迭代次数。
3. **并行**：平台若支持并行执行则并行三条检测分支；不支持时串行执行，结果等价（因为都写共享上下文），只是耗时增加。
4. **中断恢复**：交互节点中断后，恢复时从最近一次交互节点继续，已完成的节点结果从上下文缓存读取，避免重复请求（也避免重复计入限速预算）。

## 九、连线检查清单（提交前自检）

- [ ] 每条边的「出」类型与下一条边的「入」类型一致
- [ ] 不存在绕过 ③ 合规闸门 / 子流程⑧ 直接发起请求的边
- [ ] 所有分支边都有明确条件，没有"默认全走"
- [ ] fork 的每条分支都能到达 join，不存在断头分支
- [ ] 环都有退出条件与最大次数
- [ ] 阻断边确实跳到结束节点，而不是"静默跳过"
- [ ] 交互节点都有超时策略
- [ ] 失败路径（改道 / 降级 / partial）能在报告中体现，不吞异常

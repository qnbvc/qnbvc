### 介绍（限 1024 字，直接复制）

```
【角色定位】
面向政企网站的授权范围内安全巡检智能体，用于替代理工周期性巡检。不做渗透测试、不做破坏性验证，只做"发现—验证—跟踪—闭环"。

【能力范围】
1. 授权与范围管理：录入授权域名/IP 段/URL 前缀、巡检范围（含排除规则）、周期与时间窗，以及本单位敏感信息定义（关键词/正则/文件类型/样例样本）。
2. 资产与页面发现：子域枚举、存活探测与指纹识别、页面爬取、前端 JS 接口提取、资源清单与页面快照，并与上一轮快照比对做增量巡检。
3. 三类风险检测：
   · 漏洞与弱配置：组件版本与已知漏洞比对、模板化非入侵 POC、安全响应头、目录列表、暴露面（备份文件/.git/调试端点）、TLS 配置；
   · 页面篡改与挂马：正文与 DOM 结构基线比对、视觉截图比对、恶意外链与域名信誉、隐藏元素与混淆脚本特征；
   · 敏感信息泄露：自定义关键词/正则/文件类型/样例指纹匹配，覆盖凭据密钥、个人信息、源码与文档元数据，命中结果自动脱敏。
4. 结果处理：跨工具去重与关联、非破坏性二次确证、风险分级（P0–P3），每条风险给出证据、影响与分角色修复建议。
5. 闭环运营：定时巡检、基线对比（新增/变更/修复/复现）、分级告警、复测、报告导出（Markdown/PDF/Excel）。

【边界与限制】
· 仅在已授权范围内执行；所有出站请求经合规闸门校验（范围、限速、时间窗），越界即拒绝并记入审计日志；
· 默认仅执行被动档（只读采集）与受控探测档，主动验证档默认关闭、需显式授权；
· 禁止弱口令爆破、注入数据导出、文件上传、拒绝服务类操作；
· 所有结论均可回溯到证据与来源工具，支持复测验证。

【适用场景】
政企门户、办事系统及下属单位站点的周期性安全巡检与敏感信息防泄露检查。
```

**② 交互节点的表单字段**（建议分 3 步问）：

1. 授权基础信息：授权编号、授权主体、域名/通配子域、IP 段、URL 前缀、有效期、责任人、授权书附件
2. 巡检范围与策略：包含路径、排除路径、端口、爬取深度、并发、单次请求预算、时间窗、冻结期、默认档位、T1/T2 资产白名单
3. 敏感信息定义：关键词、正则（名称+表达式）、文件类型、样例文件、白名单、脱敏策略

> 若平台交互节点不支持文件上传，样例先降级为"文本片段"，验收时再补文件解析。

### ① 开始节点的输入参数与变量（照着填）

**输入参数**（`input` 必填，其余可选）：

| 参数名称 | 参数类型 | 参数描述 | 默认值 | 是否必填 |
| --- | --- | --- | --- | --- |
| `input` | String | 用户输入：巡检指令 / 配置录入 / 复测请求 | 留空 | ✅ |
| `trigger_type` | String | 触发方式：manual / schedule / api | `manual` | ☐ |
| `target` | String | 本次巡检目标（域名或 URL），留空则按全量范围巡检 | 留空 | ☐ |
| `request_id` | String | 幂等键，同一 request_id 重复调用不重复执行 | 留空 | ☐ |

**变量**（流程内部共享，随节点逐步被填充）：

| 参数名称 | 参数类型 | 参数描述 | 值 |
| --- | --- | --- | --- |
| `run_id` | String | 本轮巡检唯一 ID | 空 |
| `auth_config` | Object | 授权与巡检范围配置（② 产出） | 空 |
| `sensitive_rules` | Object | 敏感信息规则集（敏感定义转规则节点产出） | 空 |
| `scope_snapshot` | Object | 授权范围快照，合规闸门的唯一依据（③ 产出） | 空 |
| `assets` | Array | 资产清单（④ 产出） | 空 |
| `pages` | Array | 页面与资源清单（④ 产出） | 空 |
| `raw_findings` | Array | 各工具原始命中，未去重（⑤ 产出） | 空 |
| `findings` | Array | 去重、验证、分级后的风险条目（⑥⑦ 产出） | 空 |
| `changes` | Object | 基线对比结果：新增 / 复现 / 已修复（⑩ 产出） | 空 |
| `audit_log` | Array | 审计记录：每次请求与放行 / 拦截 | 空 |
| `request_count` | Number | 本轮已发出请求数，用于预算控制 | 0 |
| `run_status` | String | 本轮状态：running / partial / done | `running` |

> 类型下拉若没有 Object / Array，则选 String 并约定存 JSON 文本。

**"是否公开"怎么勾**：默认**全部不勾（不公开）**。

| 变量 | 建议 | 理由 |
| --- | --- | --- |
| `run_id` / `request_count` / `audit_log` | 不公开 | 内部运行标识与审计数据 |
| `auth_config` / `scope_snapshot` / `sensitive_rules` | 不公开 | 含授权范围与检测规则，属敏感配置，暴露即扩大攻击面 |
| `assets` / `pages` / `raw_findings` / `findings` | 不公开 | 中间数据；完整证据链不应直接暴露给调用方 |
| `changes` | 不公开 | 对外展示的差异摘要应由报告节点显式产出 |
| `run_status` | 可公开 | 需要在对话里显示"巡检进行中/已完成"时勾选 |

> 设计原则：**对外可见的内容由结束节点/报告节点显式产出，而不是靠公开内部变量**——这样才能统一做脱敏与筛选，也符合最小暴露原则（可写进作品的合规设计点）。
>
> 若该平台把"公开"解释为"允许下游节点引用"（勾了才能读到），则反过来——**必须全部勾选**。判断方法：① 鼠标悬停 ⓘ 看说明文字；② 做最小验证：只勾 `run_status`，保存后拖一个下游节点试着引用它，能引用则说明"公开=可引用"，此时全部勾上。

**高级配置**：历史会话轮数保持 5（支撑"上次那条修好了吗"这类追问即可，不建议超过 10）。

> ⚠️ 开始节点面板里没有定时触发配置 → 定时巡检需在平台独立的"触发器 / 定时任务"入口配置，或退化为手动触发 + ③ 节点内的定时器工具。

### ② 交互节点怎么填

面板分两块：**消息配置** = 机器人先说什么；**问答配置** = 问什么、答案存成哪个参数。
**问答的"问题名称"就是下游引用的变量名**（英文），"问题内容"才是给用户看的中文。

**消息配置**（先给一段引导，再开始提问）：

| 消息名称 | 输出内容 | 输出参数 |
| --- | --- | --- |
| `引导语·授权巡检配置` | 类型选 **输入**，内容：`您好，开始配置巡检前请准备好：① 授权域名/IP 段 ② 需要排除的路径 ③ 巡检周期与时间窗 ④ 敏感信息定义。我会先校验授权范围，范围外的目标一律不发起请求。` | 留空 |

可选润色：再加一条消息，"输出内容"选 **引用** 并绑定 `开始节点.input`，回显用户刚说的话（演示体验加分）。

> **"是否流式"选"否"**。这条消息是固定引导语（短、静态），流式没有收益，反而让用户多等一下才开始答题；
> 流式只值得用在**模型节点生成的长文本**上（报告正文、风险解释），那是 ⑦ / 报告节点的事，不是交互节点。

**问答配置**（**6 行**；问题名称用英文，严格与下游节点一致）：

| # | 问题名称 | 问题类型 | 问题内容 |
| --- | --- | --- | --- |
| 1 | `auth_targets` | 填空 | 请输入授权域名或 IP 段（多个用英文逗号分隔）。示例：`portal.example.gov.cn, *.example.gov.cn` |
| 2 | `scope_exclude` | 填空 | 请输入需要**排除**的路径（没有就填"无"）。示例：`/admin/export, /api/personal/*` |
| 3 | `schedule` | 填空 | 请输入巡检周期与允许的时间窗。示例：`每天 02:00 巡检，仅 02:00-05:00 发请求` |
| 4 | `sensitive_keywords` | 填空 | 请输入敏感关键词（英文逗号分隔）。示例：`内部资料, 仅供内部使用` |
| 5 | `sensitive_regex` | 填空 | 请输入敏感信息正则，**多条用分号分隔**（正则里常含逗号，别用逗号分隔）。可留空。示例：`(?<!\d)1[3-9]\d{9}(?!\d); \d{17}[\dXx]` |
| 6 | `sensitive_sample` | 单文件 | 如有敏感信息样例文件（Excel/Word/PDF）可上传；没有可直接跳过 |

> 填写提示里务必写"英文逗号分隔"——代码节点靠逗号拆分，中文逗号会拆不开。
> **文件类型不单独提问**：在 ③ 代码节点里给默认值 `pdf, docx, xlsx, csv, sql, bak, env, log`，少问一轮。
> 这 6 个字段都是**结构化录入**，③ 代码节点可以直接校验，因此第一版**不需要模型节点**。
> 想省一轮：`sensitive_sample` 可删（赛题的"关键词/正则/文件类型/样例"是四选一，样例是可选加分项），删掉后是 5 问。

**迭代配置 · 是否迭代**：选 **否**（多行问答一次问完即可）。选"是"适合"还要再添加一个域名吗？"这种循环添加场景，比赛第一版不需要。

**高级配置**：

| 项 | 面板默认 | 建议 |
| --- | --- | --- |
| 节点超时时间 | 300 | 保持 300（5 分钟给用户填表） |
| 回答超时时间 | 30 | ⚠️ **改为 300**——30 秒用户还没读完问题就超时了，演示现场必翻车 |
| 最大运行次数 | 30 | 保持（仅迭代为"是"时才生效） |

**异常配置 · 节点异常处理**：选 **失败后返回**。理由：交互失败（用户超时/取消）时绝不能带着不完整的配置继续往下扫，宁可终止并提示重来。

**输出参数**：确认列表里出现 6 个问答参数（`auth_targets` / `scope_exclude` / `schedule` / `sensitive_keywords` / `sensitive_regex` / `sensitive_sample`）+ 系统自带的 `_error_code`、`_error_message`。若问答参数没自动加进来，手动补上并写参数说明。

### ③ 代码节点怎么填（合规闸门）

代码本体已写好并本地验证通过：`framework/platform/gate_code_node.py`（纯标准库，直接全选复制粘贴到"代码配置"框）。

**输入参数**：删掉默认的 `input` 行，改成 5 行，每行「值」都选 **引用** → 选上一步交互节点的同名输出：

| 参数名 | 值 |
| --- | --- |
| `auth_targets` | 引用 → 交互节点 · `auth_targets` |
| `scope_exclude` | 引用 → 交互节点 · `scope_exclude` |
| `schedule` | 引用 → 交互节点 · `schedule` |
| `sensitive_keywords` | 引用 → 交互节点 · `sensitive_keywords` |
| `sensitive_regex` | 引用 → 交互节点 · `sensitive_regex` |

**输出参数**：面板自带的 `result_key` 行**不能删除，但可以改名**——它就是平台留给你写第一个输出参数的占位行，直接改名为 `scope_snapshot` 复用；再新增 5 行。`_error_code` / `_error_message` 是系统行，不用动。

每行的"参数值"选 **JsonPath**（代码节点 `return` 的是 JSON 对象，靠路径取字段）：

| 参数名 | 参数类型 | 值类型 | 参数值 | 说明 |
| --- | --- | --- | --- | --- |
| `scope_snapshot` | String | JsonPath | `$.scope_snapshot` | 授权范围快照（JSON），后续所有工具调用的边界依据 |
| `sensitive_rules` | String | JsonPath | `$.sensitive_rules` | 敏感信息规则集（JSON） |
| `errors` | String | JsonPath | `$.errors` | 错误清单（JSON 数组），非空 = 校验未通过 |
| `warnings` | String | JsonPath | `$.warnings` | 告警清单（JSON 数组） |
| `valid` | Number | JsonPath | `$.valid` | 1 = 通过，0 = 未通过 |
| `summary` | String | JsonPath | `$.summary` | 一句话结论，可直接展示给用户 |

> 参数名必须与代码 `return` 字典的 key 一字不差；值类型五种（输入 / 引用 / 渲染 / 正则 / JsonPath）里，只有 JsonPath 适合"从代码返回值里取字段"。

**其余配置**：迭代 = 否；超时 = 300；最大运行次数 = 30；异常处理 = **失败后返回**。

> 设计要点：**校验不通过 ≠ 节点异常**。校验失败返回 `valid=0 + errors`，让上游提示用户改；
> 只有代码本身出错才抛异常。否则用户输错一个域名就会把整条流程打断。

## 第 3 步 · 三个智能体节点的子画布

每个智能体节点内部是一张子画布，对外只有一组入参/出参：

**子流程① 授权与配置**（被 ②③ 调用）
`交互·录入授权与规则` → `代码·格式与范围校验` → `模型·敏感定义转规则` → `代码·入库与生效`

**子流程② 巡检执行**（被 ④⑤ 调用）
`工具·子域/爬虫/指纹` → `代码·URL 归一化与 Diff` → `工具·三类检测执行` → `代码·标准化为 Finding`

**子流程③ 结果闭环**（被 ⑥⑦⑧⑨ 调用）
`代码·去重/验证/分级` → `模型·影响与修复建议` → `工具·告警推送` → `交互·复测与报告导出`

> 平台若不支持子画布，就把这 12 个节点直接铺在主画布上（主流程变 22 个节点），连线顺序不变。

| 档位 | 工具 | 用途 |

## 第 5 步 · 模型节点提示词（直接复制）

### ⑦ 解释与修复建议

```
你是网站安全巡检报告解释器。输入是风险条目 JSON 数组，每条包含：finding_id、标题、类型、等级、URL、位置、证据摘要、规则 ID。
请为每条输出：
1) impact：一句话说明"谁能利用、需要什么前置条件、会造成什么业务或数据影响"，不超过 80 字，不夸大；
2) remediation：分角色给出可执行整改项（开发 / 运维 / 安全），每项一句话，并附验证方法；
3) cwe：若输入未给出，补充最贴切的 CWE 编号。
约束：只依据输入证据推理，不得虚构证据或扩大影响面；证据不足时输出"证据不足，建议人工复核"；严格输出 JSON 数组，字段为 finding_id、impact、remediation、cwe。
```

### 子流程① 内的"敏感定义转规则"

```
你是敏感信息规则编译器。输入为本单位对敏感信息的自然语言描述与样例文本。
输出结构化 JSON：keywords[]、regex[{name, pattern, reason}]、file_types[]、whitelist_suggestions[]、false_positive_risks[{rule, risk, advice}]。
约束：正则必须可编译；禁止 .* 这类过宽模式；每条规则必须给出匹配理由；必须列出误报风险与建议白名单；不确定的一律标注"需人工确认"，不要替用户扩大范围。
```

### ⑧ 告警摘要（可选）

```
你是安全告警摘要器。输入为本轮 findings 与基线对比结果（新增/复现/已修复）。
输出一段不超过 120 字的告警正文：先说最高危的 1~2 条（含资产与影响），再说本轮变化（新增 X 条、复现 Y 条、疑似修复 Z 条），最后给出建议动作。
约束：不夸大、不堆砌；P0/P1 才进入即时告警，其余进日报。
```

## 第 7 步 · 联调顺序与验收

按这个顺序联调，每步都能独立验证，出问题好定位：

1. **②③ 先通**：录入一个授权域名 → 看闸门是否正确拒绝范围外域名（这一步必须先过，是合规底线）。
2. **④⑤ 再接**：能列出页面清单，且每个工具调用都出现在审计日志里。
3. **⑥⑦ 再通**：同一漏洞被两个工具命中时，结果合并成 1 条且来源显示 2 个工具。
4. **⑧⑨⑩ 收尾**：能导出报告；改一处页面再跑一轮，能看到"新增 / 复现 / 已修复"。
5. **合规演练**：故意输入范围外域名与未授权 T1 资产，确认被拦截并留痕。

验收 5 条（对应评分项）：

- [ ] 授权与敏感信息定义可现场新建并立即生效（功能完整性）
- [ ] 报告里能看到"原始命中 N → 去重后 M"（检测效果）
- [ ] 每条风险都有证据 + 影响 + 修复建议（智能体能力）
- [ ] 范围外目标被拒绝并记录（安全合规）
- [ ] 一键可复现、能导出报告（工程化）

## 时间紧？先搭 4 节点最小闭环

```
① 开始 → ② 交互·授权录入 → ⑤ 智能体·（发现+检测合一） → ⑦ 模型·解释与建议 → ⑩ 结束
```

跑通这条线（能发现页面、能报出风险、能给建议），再加 ③ 合规闸门、⑥ 去重验证、⑧ 告警报告、⑨ 复测。**顺序别反**：合规闸门和去重验证这两个是评分刚需，越早加越好。

| 3b | 自规划·拒绝提示 | 自规划 | 3a 输出 | 拒绝说明 | 未授权时的终止话术（结束节点不能配条件） |
| 2b | 交互·巡检参数 | 交互 | — | 域名/范围/周期/敏感规则/告警通道 | 8 问，带默认值 |

| ⑤d | 工具·run_inspection | 工具 | 节点参数 `site_id` 等 | 巡检结果 | 调用恒巡云能力集，补齐篡改/挂马/组件/基线能力 |

## 三、数据流（连线与入参绑定）

| 上游 | 输出 | 下游入参 | 说明 |
| --- | --- | --- | --- |
| 2a | 回答 | 3a 输入 | 授权闸门的判据 |
| 3a | `OK`/`DENIED` | 边条件 | `contains(result_key,"OK")` |
| 3a 或 2b | — | ③ 输入 | 授权快照 + 参数 |
| ③ | `gate_payload` | ④、⑤、⑤b、⑤c | 授权边界与敏感规则 |
| ④ | `pages_payload` | ⑤、⑤b、⑧ | 页面清单；⑧ 用它算覆盖与拦截统计 |
| ⑤ | `findings_payload` | **⑥** | 被动线主线（**必须绑 ⑤，不能绑 ⑤b**） |
| ⑤b | 文本 | ⑤c `tool_payload` | 自规划节点输出可能是散文，⑤c 负责抠 JSON |
| ⑤d | 结果 | ⑤c `mcp_payload` | 能力集结果，与 ⑤b 两路合并 |
| ⑤c | Finding 数组 | ⑥ `tool_findings_payload` | 归一后的工具线结果 |
| ② 或常量节点 | 抑制规则 JSON | ⑥ `suppress_payload` | 白名单/已知例外 |
| ⑥ | `findings`+`stats` | ⑥b、⑧ | ⑥b 只喂模型，⑧ 用全量渲染 |
| ⑥b | 精简数组 | ⑦ 输入 | 条数封顶 + 证据截断 |
| ⑦ | `explain_payload` | ⑧ | 影响与整改建议 |
| ⑧ | 报告文本 + 文件 | ⑨/⑩ | 文本含"报告交付"区块 |
| ⑨ | 复核结论 | 下一轮 ⑥ 抑制规则 | 人工复核闭环 |

**易错点**：代码节点的入参名必须与代码里 `_input(args,"xxx")` 一字不差，写错会静默取空值；
平台"引用"上游输出时会包一层 `{"result_key": ...}`，各节点均已做剥壳。

## 四、两条检测线的分工

| | 被动检测线（⑤） | 工具线（⑤b + ⑤d） |
| --- | --- | --- |
| 动作性质 | 只读 GET / HEAD，秒级 | MCP 工具调用，分钟级 |
| 覆盖 | 响应头基线、敏感关键词/正则/文件类型、恶意页面特征、敏感文件可达性 | TLS 配置、子域名线索、HTTP 参数、页面篡改、挂马、组件风险、基线对比 |
| 确证方式 | 只读复采，命中即确证；两次未命中才转待复核 | 有复采线索才确证；协议层结论标 `unverified`，不被 HTML 复采否定 |
| 贡献 | 确定性结论、证据可复采 | 补齐自研短板、提供交叉印证 |

汇合点在 ⑤c → ⑥：跨来源同一条结论合并为**两线交叉印证**并提高置信度；
来源构成为"被动检测线 X 条 · 工具线 Y 条 · 两线交叉印证 Z 条"，三者相加等于去重后条数。

## 五、四个闭环

1. **检测闭环**：资产发现 → 检测 → 去重验证分级 → 报告 → 告警。
2. **误报闭环**：复采确证（含抖动重试）→ 待复核 → 白名单/抑制规则 → 报告附录留痕。
3. **基线闭环**：第一轮 `mode=baseline` 建基线 → 第二轮 `mode=regular` 出篡改/新增 → 整改后 `mode=retest` 复测。
4. **评测闭环**：靶场运行 → 智能体巡检 → 导出 JSON → 适配器转换 → 评分器出召回率/准确率/误报率。

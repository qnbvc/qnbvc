## 提示词（整段复制到「提示词」框）

```
你是"开源安全工具编排员"。上游会给你【授权边界】和【已发现的页面/主机清单】，
你要调用已授权的 MCP 工具做非破坏性检测，并把结果统一成标准 JSON 输出。

【授权边界（不可逾越）】
{{.scope_payload}}

【已发现的页面/主机清单】
{{.input}}

【可用工具与分工（两个都要用）】
- SSL TLS检测：TLS 与证书类检查——证书有效期、证书链是否完整、是否自签名、
  是否仍支持 SSLv3 / TLS 1.0 / TLS 1.1、是否启用弱加密套件
- Nuclei漏洞扫描：模板化检查——缺失的安全响应头、暴露的敏感文件与目录、
  组件版本与默认页面线索、目录列表等

执行顺序：先对每个目标做 TLS 检测，再用 Nuclei 做模板化扫描。

【硬性约束（违反任意一条即视为任务失败）】
1. 只对清单里出现过的主机名执行操作，清单外的域名与 IP 一律不碰
2. 严格只读非破坏：不做 SQL 注入、口令爆破、文件上传、写入删除、提权、压力测试
3. Nuclei 只用非入侵类模板：配置与暴露类（http-missing-security-headers、http-exposures、
   technologies、ssl、misconfiguration），跳过 fuzz / intrusive / dos / brute-force 类模板
4. 限速：单目标不超过每秒 5 次请求；整轮检测控制在 5 分钟以内
5. 不输出任何攻击载荷、exp 代码或漏洞利用步骤
6. 只记录工具真实返回的结果，不推断、不补全；工具失败最多重试 1 次，仍失败就跳过该工具并继续
7. 清单为空时，最终回复就是 []

【耗时与调用预算（必须遵守，否则会拖死整条流程）】
1. 工具调用总预算：最多 4 次——TLS 检测 1 次，Nuclei 最多 3 次，达到预算立即汇总输出
2. Nuclei 只跑配置与暴露类模板（misconfiguration、exposures、ssl、technologies），
   模板数量控制在 20 个以内；工具若提供模板 / 速率 / 超时参数，按"4 类模板、5 QPS、单次 120 秒"设置
3. 单目标整体耗时不超过 180 秒：超过就跳过该目标，把已经拿到的结果先输出
4. 只对本轮清单里的目标执行，目标数量超过 3 个时只取前 3 个，其余在标题里注明"未检测"

【执行步骤】
1. 从清单里提取去重后的主机与 URL 列表
2. 逐个目标先做 TLS 检测，再做 Nuclei 模板化扫描
3. 每条命中记录：工具名、命中的模板/规则 ID、目标 URL、关键证据片段、可复采的验证线索

【输出格式（严格输出下面的 JSON 数组）】
[
  {
    "asset": "主机名，如 fangxiangji.gymjilv.cn",
    "url": "具体 URL，如 https://fangxiangji.gymjilv.cn/",
    "type": "vuln 或 misconfig 或 leak 或 malware 或 tamper",
    "rule_id": "NUCLEI.http-missing-security-headers 或 SSL_TLS.WEAK_PROTOCOL 这类工具名.规则ID",
    "title": "简短中文标题，如 缺少安全响应头",
    "severity": "critical 或 high 或 medium 或 low 或 info",
    "tool": "写清这条是哪个工具产出的：Nuclei漏洞扫描 或 SSL TLS检测",
    "tier": "T1",
    "location": "命中的位置，如 content-security-policy 响应头 / TLS 配置 / /backup.zip",
    "evidence": "一句话证据，含关键响应片段；不要包含任何敏感值",
    "verify_hint": "复采时能用来复现的关键字符串，如缺失的响应头名或命中路径；没有就留空",
    "confidence": 0.8
  }
]

【输出契约】你的最终回复就是本次任务的接口返回值：直接给出上面的 JSON 数组本身。
不要写寒暄、分析过程或结论总结，也不要用 markdown 代码块包裹。
没有发现问题时，最终回复就是 []。
```

## 加第二个 MCP 之后必须同步改的 5 处

| # | 位置 | 原来的值 | 改成 |
| --- | --- | --- | --- |
| 1 | 环境变量 `TOOL_WHITELIST` | `SSL TLS检测` | `SSL TLS检测,Nuclei漏洞扫描` |
| 2 | 提示词第 3 条硬性约束 | "只允许调用这一个工具：SSL TLS检测" | 删掉这句，改用上面【可用工具与分工】的写法 |
| 3 | 节点超时 | 600 | **900**（Nuclei 模板扫描比 TLS 握手慢得多） |
| 4 | 提示词末尾 | 无输出契约 | 补上【输出契约】那一段 |
| 5 | ⑥ 的 `tool_findings_payload` | 引用 ⑤b | 引用 **⑤c**（如果已建规范化节点） |

另外：**⑤b 的超时先设 300 秒**，让它最坏情况下 5 分钟失败退出（异常配置是"失败后继续"，
不会拖死主线），而不是在画布上无限"运行中"。等双工具稳定出结果后，再按实际耗时调整。

第 1 处最容易漏：白名单里只有 TLS 检测时，模型即使看见 Nuclei，也会因为"只允许这个工具"而不用它。

## 不需要改的地方

- **⑤c 规范化节点**：不区分工具来源，按字段归一即可，代码不用动。
- **⑥ 的跨来源归一化**：`_normalize_rule()` 已把 `http-missing-security-headers` 这类模板映射到
  `MISCONFIG.MISSING_HEADER.<响应头名>`，与被动线报的同一条能合并成"两线交叉印证"。
- **⑥ 的确证规则**：Nuclei 命中若带 `verify_hint`，⑥ 会复采确证并提置信度；不带则标 `unverified`
  （诚实标注，不冒充确证）。所以提示词里要求给出 `verify_hint` 是有回报的。
- **合规基线**：`BLOCKED_ACTIONS` 可以再补 `fuzz,暴力破解,注入,压测`，与提示词第 3 条呼应。

## 验收标准

跑一轮 `fangxiangji.gymjilv.cn`，⑥ 的日志应当出现：

```
[去重验证分级] 来源构成：被动检测线 5 条（⑤）· 工具线 0 条（⑤b + MCP）· 两线交叉印证 1 条（三者合计 = 去重后 6）
```

即：Nuclei 报的缺失安全响应头与被动线报的同一组头缺失合并成一条交叉印证，
报告的"检测来源"会显示 `被动检测线（⑤）+ 工具线（⑤b + MCP）交叉印证 | headers-baseline,nuclei`。

## 双工具卡住时的分阶段排查

两个工具一起挂，慢在谁身上看不出来。按下面的顺序退回去定位：

| 阶段 | 配置 | 目的 |
| --- | --- | --- |
| 1 | 只挂 **Nuclei漏洞扫描**，提示词里的工具分工只留 Nuclei | 单独确认 Nuclei 能返回、耗时多少 |
| 2 | 只挂 **SSL TLS检测** | 确认 TLS 侧仍然正常（这条路已验证可行） |
| 3 | 两个都挂，加上面的【耗时与调用预算】 | 确认总耗时可控 |

演示当天的保底策略：⑤b 是"增强线"，主线 `④ → ⑤ → ⑥ → ⑦ → ⑧` 本身就能出完整报告。
先把主线跑通、把报告展示出来，再单独演示 ⑤b 的工具编排与"两线交叉印证"，
不要让它卡在关键路径上。

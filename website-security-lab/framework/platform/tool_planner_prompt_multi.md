# ⑤b 自规划节点提示词 · 当前版（三工具）

> **这份是当前要用的版本。** 已挂 MCP：**SSL TLS检测**、**子域名发现**、**HTTP参数发现**
> （Nmap 与 Nuclei 均已摘除：前者是端口扫描、合规风险最高且耗时不可控，后者卡在模板拉取）
> 节点：自规划节点 ｜ 模型：**HengNao-v4（256K）** ｜ 超时：**300** ｜ 异常：**失败后继续** + 自定义返回 `{"result_key": "[]"}`
> 接线：`④ → ⑤ → ⑤b → ⑤c → ⑥`

三个工具的"性格"差别很大：TLS 检测是秒级只读；子域名发现会碰到授权范围外的资产；
HTTP 参数发现会产生成百上千次请求，必须限速限量。
所以这份提示词的重点不是"多跑几个工具"，而是**把每个工具的边界单独钉住**。

---

## 提示词（整段复制到「提示词」框）

```
你是"开源安全工具编排员"。上游给你【授权边界】和【已发现的页面/主机清单】，
你要在授权范围内调用 MCP 工具做非破坏性检测，并把结果统一成标准 JSON 输出。

【授权边界（不可逾越）】
{{.scope_payload}}

【已发现的页面/主机清单】
{{.input}}

【工具分工与各自的边界】

1. SSL TLS检测——TLS 与证书：证书有效期、证书链完整性、是否自签名、
   是否仍支持 SSLv3 / TLS 1.0 / TLS 1.1、弱加密套件。
   边界：只做握手与证书读取。

2. 子域名发现——从公开的证书透明日志与 DNS 枚举子域。
   边界：这是"资产线索"收集，不是漏洞检测。新发现的子域一律**只登记、不发请求**，
   写进输出里的 pending_assets 字段，标注"待授权确认"。
   只有当某个子域本来就出现在上游清单里时，才允许继续对它做其他检测。

3. HTTP参数发现——对清单里的 URL 枚举参数名，用于判断是否存在可疑的查询入口。
   边界：只用 GET 读取；单个 URL 的参数枚举总量不超过 50 次请求；
   发现可疑参数只记录名称与位置，绝不发送注入类载荷、绝不修改任何数据。

【执行顺序与调用预算】
1. 先 SSL TLS检测（1 次），再子域名发现（1 次），再 HTTP参数发现（1 次）——
   总调用不超过 3 次，达到预算立刻汇总输出
2. 每个工具失败最多重试 1 次，仍失败就跳过该工具继续，不要中断
3. 任一工具超过 120 秒未返回，放弃该工具继续下一个；整轮不超过 300 秒
4. 目标数量超过 3 个时，只对前 3 个执行，其余在 title 里注明"未检测"

【硬性约束（违反任意一条即视为任务失败）】
1. 只对清单里出现过的主机名执行操作；清单外的域名与 IP 一律不碰（子域名发现的新资产仅登记）
2. 严格只读非破坏：不做 SQL 注入、口令爆破、目录爆破、文件上传、写入删除、提权、压力测试
3. 不输出任何攻击载荷、exp 代码或漏洞利用步骤
4. 只记录工具真实返回的结果，不推断、不补全；把哪个工具产出的写进 tool 字段
5. 清单为空时，最终回复就是 []

【输出格式（严格输出下面的 JSON 对象）】
{
  "findings": [
    {
      "asset": "主机名",
      "url": "具体 URL",
      "type": "vuln 或 misconfig 或 leak 或 malware 或 tamper",
      "rule_id": "工具名.规则ID，如 SSL_TLS.WEAK_PROTOCOL、SUBDOMAIN.PENDING_ASSET",
      "title": "简短中文标题",
      "severity": "critical 或 high 或 medium 或 low 或 info",
      "tool": "写清是哪个工具产出的：SSL TLS检测 / 子域名发现 / HTTP参数发现",
      "tier": "T1",
      "location": "命中位置，如 content-security-policy 响应头 / TLS 配置 / /search?q=",
      "evidence": "一句话证据，含关键片段；不要包含敏感值",
      "verify_hint": "复采时能复现的关键字符串，没有就留空",
      "confidence": 0.8
    }
  ],
  "pending_assets": ["新发现的、尚不在授权清单内的子域，标注待授权确认；没有就留空数组"]
}

【输出契约】你的最终回复就是本次任务的接口返回值：直接给出上面的 JSON 对象本身。
不要写寒暄、分析过程或结论总结，也不要用 markdown 代码块包裹。
没有任何发现时，findings 就是空数组。
```

## 节点配置要改的地方

| 配置项 | 原来的值 | 改成 |
| --- | --- | --- |
| 环境变量 `TOOL_WHITELIST` | `SSL TLS检测` | `SSL TLS检测,子域名发现,HTTP参数发现` |
| 环境变量 `MAX_QPS` | `5` | `3`（参数发现会产生大量请求，压一压） |
| 环境变量 `BLOCKED_ACTIONS` | 旧值 | 追加：`端口扫描,目录爆破,参数爆破,爆破,fuzz,压测,注入` |
| 节点超时 | 600 / 900 | **300**（最坏 5 分钟失败退出，不拖死主线） |
| 异常配置 | 失败后继续 | 失败后继续 + 自定义返回 `{"result_key": "[]"}` |
| 提示词 | 单工具版 | 上方多工具版 |
| ⑥ 的 `tool_findings_payload` | 引用 ⑤b | 引用 **⑤c** |

**不建议一次挂四个还开着 600 秒以上的超时。** 四个工具串起来跑，单轮最坏耗时是它们之和；
300 秒的超时配合提示词里的调用预算，才能保证它一定在可接受的时间内收敛。

## 每个工具的合规边界（这部分是给评委看的）

| 工具 | 动作性质 | 边界控制 | 风险等级 |
| --- | --- | --- | --- |
| SSL TLS检测 | 只读握手 | 单次握手，无重试放大 | 低 |
| 子域名发现 | 只读公开数据源 | 发现的新资产**只登记、不探测** | 低 |
| HTTP参数发现 | 主动 GET 枚举 | 单 URL ≤ 50 次请求、5 QPS 以内、不发送载荷 | 中 |

**已摘除的工具**：Nmap（端口扫描，唯一可能被判定"超出网站巡检授权范围"的动作，
且全端口扫描耗时不可控）、Nuclei（需要拉取模板，容器无外网时会挂起）。
三个轻量工具已经足够体现"按目标类型选工具"的编排能力。

`pending_assets` 这一项值得保留：它把"发现范围外资产、但克制地没有去碰"这个动作留了痕，
正好对应赛题"授权边界、最小权限"的评分点。⑤c 会把这一项透传到日志里。

---

## 验收标准

1. ⑤b 在 300 秒内返回，输出是 JSON 对象（不是散文）；
2. ⑤c 的日志显示归一后条数，并打印 `pending_assets`（如果有）；
3. ⑥ 的日志显示 `来源构成`，其中"工具线"条数大于 0；
4. 若工具线报的缺失响应头与被动线重合，`两线交叉印证` 计数 ≥ 1。
